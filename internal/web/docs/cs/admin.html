Personál, nastavení a aktualizace

Účty personálu

  • Správci smějí vše, včetně účtů personálu a nastavení serveru.
  • Operátoři spravují balíčky, zákazníky, domény a schránky.
  • Pozorovatelé se jen dívají.

Každý účet se přihlašuje heslem a ověřovací aplikací. Protokol auditu zaznamenává každou změnu; každý záznam je s předchozím zřetězen pomocí hashe, takže pozdější úpravy protokolu se odhalí.

Nastavení poštovního serveru

  • Název hostitele: úplný název serveru (např. mail.example.com). Musí se překládat na veřejnou adresu serveru a tato adresa by se měla zpětně překládat na něj (záznam PTR u vašeho poskytovatele hostingu); jinak ostatní servery považují vaši poštu za spam. Kontrola v části Název hostitele a záznamy PTR ukáže pro každou adresu, ze které server odesílá (IPv4 i IPv6), zda na ni název hostitele ukazuje a zda její záznam PTR ukazuje zpět.
  • Posílat poštu jiným serverům jen přes IPv4: pro server s IPv6, jehož poskytovatel nemůže pro adresu IPv6 nastavit záznam PTR (Gmail a Outlook takovou poštu odmítají). Příjem přes IPv6 funguje dál.
  • Největší zpráva pro příchozí a odchozí poštu.
  • Kontrola virů: ClamAV kontroluje každou zprávu a infikovaná pošta se odmítá („Virus found“). Zapnutí sám nainstaluje ClamAV (asi 1 GB paměti); kontrola začne, jakmile se stáhnou virové signatury, o několik minut později. Vypnutí ClamAV opět zastaví. S bezplatnými signaturami Sanesecurity zná ClamAV i aktuální spamové, phishingové a podvodné zprávy, zprávy se škodlivými odkazy a nebezpečná makra: poštovní pomocník je každých šest hodin stahuje ze zrcadel Sanesecurity a soubor nainstaluje jen tehdy, když jeho podpis GPG odpovídá klíči Sanesecurity. Jejich spamové signatury jen přičtou 7 ke skóre spamu (zpráva jde do Junk); vše ostatní se počítá jako virus. Signatury lze používat zdarma; Sanesecurity žádá firmy o dar.
  • Rizikové přílohy (ve výchozím stavu zapnuto): programy, skripty, zástupci, obrazy disků a soubory Office s makry (.exe, .js, .vbs, .bat, .lnk, .iso, .docm, .xlsm a podobné) se odmítají v obou směrech, i uvnitř ZIP a jiných archivů; odesílateli se sdělí, ať takové soubory sdílí odkazem.
  • Podvržení odesílatelé (ve výchozím stavu zapnuto): doména, jejíž pravidlo DMARC zní p=reject, prohlašuje, že pošta, která neprojde ani SPF, ani DKIM, od ní nepochází. Taková pošta je odmítnuta („The sender domain refuses this mail (DMARC)“) a pošta z domény s p=quarantine jde do nevyžádané pošty; velcí poskytovatelé to dělají stejně. Diskusní seznamy a přeposílaná pošta porušují DMARC ze své podstaty a zůstávají na hodnocení spamu.
  • Upozornění pro administrátory: až pět adres. Dostávají v pondělí ráno týdenní přehled (přijatá, odeslaná, odložená, nedoručitelná a odmítnutá pošta, schránky, které odeslaly nejvíc, automatické blokace, stav adres serveru na blokovacích seznamech), upozornění, když se adresa serveru dostane na blokovací seznam DNS nebo z něj zmizí (kontrolováno každých šest hodin), a upozornění, když je schránka zablokována kvůli odesílání spamu. Upozornění přicházejí z postmaster@ názvu hostitele.
  • Odchozí adresy: další IP adresy serveru pro odchozí poštu, jedna na řádek s vlastním názvem hostitele (203.0.113.5 mail2.example.com). Přidělte jednu zákazníkovi na jeho stránce (Odchozí adresa): pošta zákazníka pak odchází z této adresy a představuje se tímto názvem hostitele, takže jeden zákazník, který posílá spam, nemůže pokazit pověst ostatních. Adresa musí být na serveru nakonfigurována (jinak pošta odchází z hlavní adresy), její název hostitele na ni musí ukazovat a její záznam PTR musí uvádět název hostitele. Záznam SPF navržený u každé domény zákazníka pak uvádí tuto adresu (v=spf1 mx ip4:203.0.113.5 ~all); když zónu hostuje HostZit, aktualizuje se sám. Nepoužívá se spolu se smart hostem.
  • Smart host: jen když poskytovatel blokuje port 25 nebo chce veškerou poštu přes svůj vlastní server — každá odchozí zpráva pak jde na tento server (ve výchozím stavu port 587 se STARTTLS, 465 s TLS od začátku). S uživatelským jménem jde přihlášení vždy přes TLS; heslo se ukládá zapečetěné v panelu a jako soubor čitelný jen pro root pro Postfix.
  • Ověřování domén a dedikovaný server: viz Domény, schránky a aliasy.

Jak je server sestaven

Panely běží pod neprivilegovaným uživatelem emailzit. Malý poštovní pomocník běží jako root a dělá jen pevně daný seznam úkolů: zapisuje konfiguraci Postfixu a Dovecotu z nastavení serveru (před použitím zkontrolovanou, při jakékoli chybě se vrátí staré soubory), vytváří poštovní adresář nového zákazníka a přesouvá poštu smazaných schránek do koše. Postfix a Dovecot čtou domény, schránky a hesla aplikací přímo z PostgreSQL přes pohledy jen pro čtení, takže vstupy zákazníků se nikdy nedostanou do konfiguračního souboru.

Síť a přihlášení

Panely naslouchají na portu 8444 (HostZit používá 8443). Povolené sítě, délka relace a blokování adres po neúspěšných přihlášeních jsou v Nastavení. Pokud se sami zablokujete: emailzit-server --reset-allowlist, --unblock-ip ADDRESS nebo --reset-password USERNAME (nové heslo ze standardního vstupu, nutno změnit při dalším přihlášení) na serveru jako uživatel emailzit; totéž umí nabídka nastavení appliance.

Po instalaci se k portu 8444 dostanou jen privátní sítě a server sám. Na serveru s veřejnou adresou ho potřebují i zákazníci a uživatelé pošty (webmail): přihlaste se jednou přes SSH tunel (ssh -L 8444:127.0.0.1:8444 root@SERVER, pak https://127.0.0.1:8444) a v Síť a přístup přidejte 0.0.0.0/0 / ::/0. Účty personálu zůstávají chráněny druhým faktorem a blokováním po neúspěšných přihlášeních.

Nastavení → Aktualizace a server zobrazuje také operační systém: čekající aktualizace Debianu (kontrolované automaticky dvakrát denně), zda jsou zapnuté automatické bezpečnostní aktualizace, a tlačítka pro instalaci všech aktualizací a restart celého serveru. Na appliance tam lze server SSH zapnout nebo vypnout a přesunout na jiný port (port, který server SSH odmítne, nic nezmění); tyto akce i restart také procházejí schválením čtyř očí, když je zapnuté.

Ochrana poštovních přihlášení a odesílání

  • Hádání hesel: Dovecot se před každým přihlášením poštovního programu (IMAP, POP3 a odesílání SMTP) zeptá EmailZit. Adresa s 10 neúspěšnými přihlášeními během 15 minut je odmítnuta a na hodinu zablokována ve firewallu (porty 110, 143, 465, 587, 993, 995, 4190 a 8444; port 25 zůstává otevřený pro ostatní poštovní servery). Účet napadený z mnoha adres se zpomalí, nikdy nezamkne, takže útočníci nemohou uživatele zablokovat. Takové zablokování je vidět v Nastavení → Přihlášení a zabezpečení → Blokované adresy a dá se tam zrušit; konzoli neblokuje, takže poštovní program se starým heslem nikoho nezamkne venku.
  • Limity odesílání na schránku a na zákazníka pocházejí z balíčku. Počítá se každý příjemce. Zprávy nad limit dostanou dočasnou chybu a poštovní program to zkusí později znovu. Schránka, která to dál zkouší daleko nad svůj limit (30 odmítnutých pokusů za hodinu), je automaticky zablokována pro odesílání; blokace je v protokolu auditu a personál ji ruší na stránce schránky.
  • Spamový filtr: Rspamd kontroluje každou příchozí zprávu; zjevný spam se odmítá, pravděpodobný spam jde do složky Junk (jak pravděpodobný, se nastavuje pro každého zákazníka a každou schránku, viz Domény, schránky a aliasy → Nastavení spamu). Pošta přihlášených uživatelů se podepisuje klíčem DKIM domény.
  • Spam odeslaný přihlášenými uživateli (poštovní programy, webmail, webové stránky) se odmítá již od skóre 10 a nikdy se neoznačuje ani nezdržuje. Schránka, jejíž odchozí pošta je odmítnuta jako spam nebo virus 3krát během hodiny, je automaticky zablokována pro odesílání: téměř vždy zná její heslo někdo jiný. Administrátoři dostanou upozornění (Nastavení → Poštovní server → Upozornění pro administrátory), schránka dostane upozornění do doručené pošty ve svém jazyce a blokace je v protokolu auditu; nastavte nové heslo a zrušte blokaci na stránce schránky.
  • Phishing: zprávy s odkazy, které PhishTank zná jako phishing, a zprávy, jejichž zobrazované jméno uvádí doménu tohoto serveru, zatímco adresa je cizí ("Boss acme.com" <someone@freemail.example>), dostanou před předmět [Phishing?], takže se varování zobrazí v každém poštovním programu.
  • Port 25: jako první odpovídá postscreen. Servery, které mluví před pozdravem (obvyklí spamoví roboti) nebo jsou na blokovacích seznamech DNS (samotný Spamhaus ZEN stačí; SpamCop a PSBL se počítají méně; DNSWL skóre snižuje), jsou odmítnuty dřív, než se dostanou k Postfixu. Na adresu nejvýše 20 souběžných spojení, 60 za minutu, 100 zpráv a 300 příjemců za minutu.
  • Místní DNS resolver: na serveru běží Unbound (port 5335) a Rspamd se ptá jeho, protože blokovací seznamy DNS odmítají dotazy přicházející přes velké veřejné resolvery. Tam, kde port 53 nepoužívá žádný jiný DNS server (PowerDNS z HostZit ho používá), odpovídá Unbound i tam a celý server překládá přes něj; Postfix pak dostává odpovědi ověřené DNSSEC a odesílá jen přes TLS s certifikátem uvedeným v záznamech DANE (TLSA) příjemce. Vlastní /etc/resolv.conf serveru se uchovává v /var/lib/emailzit/ a sám se vrátí, když Unbound přestane odpovídat nebo se nainstaluje HostZit.
  • MTA-STS pro odchozí poštu: domény, které zveřejňují zásadu MTA-STS v režimu enforce (Gmail, Outlook a mnoho dalších), dostávají poštu jen přes TLS, na servery uvedené v zásadě, s platným certifikátem. EmailZit zásady vyhledá a uchovává je po dobu jejich platnosti; kde pro doménu funguje DANE, použije se místo toho DANE. Nepoužívá se se smart hostem.

Schválení čtyř očí

V Nastavení → Přihlášení a zabezpečení mohou správci zapnout schválení čtyř očí (vyžaduje alespoň dva aktivní administrátory). Rizikové změny personálu se pak neprovedou hned, ale čekají v Schválení, dokud je neschválí jiný administrátor: ukončení nebo pozastavení zákazníka, smazání domény nebo schránky, reset druhého faktoru, vytvoření nebo změna účtů personálu a jejich hesel, smazání tokenů API a záloh a nastavení sítě, firemního přihlášení a zabezpečení, včetně vypnutí schválení čtyř očí. Nikdo nemůže schválit svůj vlastní požadavek (může ho stáhnout); schválená změna se provede jednou, jménem schvalujícího administrátora, a obě jména jsou v protokolu auditu; požadavek vyprší po 24 hodinách. Hodnoty formuláře čekajícího požadavku se ukládají šifrovaně. Zákazníků, kteří mění své vlastní domény a schránky, ani REST API se to netýká.

Firemní přihlášení pro personál

V Nastavení → Firemní přihlášení se personál může přihlašovat přes poskytovatele identity firmy (OpenID Connect: Microsoft Entra ID, Google Workspace, Keycloak, Authentik …): zaregistrujte tam EmailZit jako webovou aplikaci s adresou přesměrování zobrazenou na stránce a poté zadejte vydavatele, ID klienta a tajný klíč klienta. Poskytovatel potvrdí e-mailovou adresu; účet personálu, jehož uživatelské jméno je přesně tato adresa, už musí existovat (žádné účty se nevytvářejí; zákazníci a uživatelé pošty vždy používají své heslo). Web vždy vyžaduje druhý faktor: EmailZit se zeptá na svůj vlastní kód, pokud není zapnuto Důvěřovat druhému faktoru poskytovatele a token identity neuvádí, že se poskytovatel na druhý faktor zeptal (amr s mfa, otp, hwk …). Vypnutí účtu personálu v EmailZit danou osobu okamžitě zablokuje, ať poskytovatel tvrdí cokoli.

REST API pro fakturaci

V Nastavení → REST API vytvářejí správci tokeny pro fakturační systémy (například portál MaxZit) a HostZit. Token má jen oprávnění, která mu jsou dána (customers:read, customers:write, usage:read, sso:create), může být omezen na adresy a vyprší. Stránka uvádí všechna volání; zákazníci se adresují svým UUID nebo pomocí ext:<billing ID>; volání pro vytvoření přijímají Idempotency-Key, aby opakované volání nevytvořilo druhého zákazníka. POST /api/v1/customers/{id}/sso vrátí jednorázový odkaz (60 sekund), který zákazníka přihlásí do zákaznického panelu. Každé volání je v protokolu auditu jako api:<token name>.

Záloha panelu

Nastavení → Záloha panelu zapisuje každý den (a na vyžádání) šifrovaný soubor s databází, tajným klíčem serveru a certifikátem panelu, uchovává ty nejnovější a může je kopírovat do složky SFTP. Samotná pošta (/var/vmail) se zálohuje pomocí BackupZit. Obnovení: zastavte emailzit-server, spusťte emailzit-server -restore FILE -restore-passphrase-file FILE jako uživatel emailzit a znovu spusťte služby; konfigurace pošty a klíče DKIM se při startu zapíší znovu.

Export, BackupZit a WatchZit

Export na stránce zákazníka (nebo POST /api/v1/customers/{id}/export) zabalí veškerou poštu zákazníka a manifest.json s nastavením (domény, schránky, aliasy, automatické odpovědi a filtry, nastavení spamu) do /var/lib/emailzit/exports/<customer>/<time>.tar.gz; hesla, hesla aplikací, druhé faktory a klíče DKIM se vynechávají. Běží na pozadí (API odpoví úlohou: GET /api/v1/jobs/{id}); tři nejnovější exporty zákazníka se uchovávají a lze je stáhnout ze stránky nebo pomocí GET /api/v1/customers/{id}/exports/{name}. BackupZit může tuto složku zálohovat spolu se zálohou panelu, nebo celý /var/vmail. WatchZit kontroluje server pomocí GET /api/v1/server/status (token s customers:read): stav Postfixu, Dovecotu, Rspamd, Valkey a poštovního socketu pro webové stránky, zprávy ve frontě a odložené, volné místo poštovního úložiště a počet dní do vypršení certifikátu; ok je false, když některá služba není aktivní.

Import na stránce zákazníka (nebo POST /api/v1/customers/{id}/import?format=emailzit|cpanel s .tar.gz jako tělem) převezme export EmailZit nebo zálohu účtu cPanel (cpmove-USER.tar.gz; HostZit tímto způsobem předává poštovní část svého importu z cPanelu). Chybějící domény (doména nesmí patřit jinému zákazníkovi), schránky a přeposílání se vytvoří v rámci limitů balíčku (kvóta, která se nevejde, se změní na výchozí hodnotu balíčku), poté root pomocník nakopíruje Maildiry: jen do schránek tohoto zákazníka, nikdy nepřepíše soubor, nikdy nenásleduje odkazy, bez indexů Dovecotu a starého souboru kvóty (obojí se znovu sestaví). Hesla z cPanelu se nepřebírají: každá schránka dostane náhodné heslo, takže nastavte heslo každému uživateli (poštovní programy pak používají hesla aplikací). Z cPanelu se převezme pošta schránek domény, jejich kvóty a přeposílání; vlastní schránka hlavního účtu, roury do programů a catch-all se uvedou jako poznámky. Z exportu EmailZit se přenesou také nastavení spamu a uložené automatické odpovědi a filtry (začnou fungovat, když je uživatel jednou uloží). Výsledek a poznámky se zobrazí na stránce zákazníka a v úloze (GET /api/v1/jobs/{id}, pole report).

Spolu s HostZit

Když HostZit hostuje webové stránky a DNS týchž zákazníků, propojte oba v Nastavení → HostZit párovacím kódem (viz níže). EmailZit pak sám zapisuje poštovní záznamy každé domény (MX, SPF, DKIM, DMARC, MTA-STS, autoconfig) do DNS HostZit a udržuje je aktuální, když se změní název hostitele nebo klíč DKIM; doména, jejíž zónu HostZit hostuje pro téhož zákazníka, nepotřebuje ověření TXT. Pokud už zákazník má v HostZit vlastní záznamy se stejnými názvy, zachovají se a stránka domény to uvede. Postranní panel dostane přepínač do HostZit. Na serveru s oběma produkty odpovídá na portech 80 a 443 webový server HostZit; EmailZit zapisuje svou vlastní část (/etc/nginx/zit.d/emailzit/) pro autoconfig., autodiscover. a mta-sts. každé domény, jen s cestami, které používají poštovní programy a MTA-STS; panely tam nikdy nejsou dostupné.

Pošta z webových stránek. HostZit potřebuje token API EmailZit s customers:write, aby EmailZit sdělil linuxová ID uživatelů hostingových účtů každého zákazníka (PUT /api/v1/customers/{id}/web-uids). PHP funkce mail() v těchto účtech spouští /usr/sbin/emailzit-sendmail, který zprávu předá EmailZit přes /run/emailzit/submit.sock. EmailZit pozná účet podle ID uživatele procesu, přijímá poštu jen z registrovaných účtů aktivních zákazníků, dovolí webové stránce odesílat jen jako adresy vlastních ověřených domén zákazníka (Date a Message-ID se doplní, když chybí), počítá každý hostingový účet jako schránku v rámci limitů balíčku (za hodinu, za den, příjemců na zprávu a limit zákazníka spolu se schránkami) a předá zprávu Postfixu, kde se podepíše pomocí DKIM; protokol doručení ji zobrazuje jako web-<user ID>. Hostingový účet, který to dál zkouší nad svůj limit (napadená webová stránka rozesílající spam), se automaticky zablokuje; stránka zákazníka uvádí účty s jejich počty a umožňuje blokaci zrušit nebo nastavit. Programy na serveru nemohou používat vlastní sendmail Postfixu (smí jen root) a port 25 nevěří žádnému místnímu programu.

Propojení párovacím kódem. Nastavení → HostZit → Vytvořit párovací kód zobrazí kód jednou; vložte jej do HostZit v Nastavení → EmailZit. Kód platí jednou a jen deset minut, EmailZit si uchovává pouze jeho hash a nikdy se nedostane do protokolu. Oba servery si pak samy vydají navzájem token s nejmenšími oprávněními, vázaný na adresy druhého serveru, takže nikdo nepřepisuje token ručně. Stránka potom uvádí, který server je propojen, od kdy a z jakých adres jeho token platí. Zrušit spojení na kterékoli straně odvolá oba tokeny; pokud druhý server není dostupný, spojení skončí zde a stránka řekne, abyste je odstranili i tam. Spojení zadané ručně (adresa HostZit a token dns:mail) funguje dál. Adresy HostZit se musí dostat na tento panel, což na hostingovém serveru platí.

Pošta z webů na jiném serveru. Běží-li HostZit na vlastním serveru, jeho weby socket z předchozího odstavce nedosáhnou; párování proto předá i přihlášení k relay: jméno serveru, port 2587, uživatelské jméno a heslo. Jejich poštu tam přijímá vlastní submission server EmailZit, po STARTTLS a tomto přihlášení. Port je otevřený jen po dobu takového spojení a jen pro adresy toho HostZit; přihlášení nikde jinde neplatí: ani pro poštovní schránku, webmail či poštovní program. Každá zpráva se kontroluje: odesílatel v obálce musí být poštovní domény tohoto serveru nebo domény, kterou HostZit hostuje některému ze svých zákazníků (EmailZit se HostZit zeptá jednou a odpověď si pamatuje deset minut; neznámá doména je odmítnuta s 550, a dokud se HostZit zeptat nelze, odpověď je 451, aby to web zkusil později), a adresa From musí používat tutéž domenu. Limity zákazníkova tarifu počítají tuto poštu společně se schránkami; doména, jejíž zákazník v EmailZit není, smí poslat 200 příjemců za hodinu. Zpráva pak jde cestou webu na tomto serveru: podpis DKIM, kontrola odchozího spamu, protokol doručení. Stránka zákazníka tuto poštu vypisuje i s tím, co se s ní stalo, týdenní přehled ji počítá a Nastavení → HostZit ukazuje přihlášení i jeho poslední použití.
