Getting started

EmailZit is mail hosting for many domains and customers on your own server: an admin panel for the server staff, a customer panel where every customer manages their own domains and mailboxes, and pages for mail users (webmail, own password, app passwords, auto-reply, filters).

How it is built

  • EmailZit server — the panels and the REST API, running as an unprivileged user.
  • Postfix receives and sends mail (SMTP on port 25, submission for mail programs on 465 and 587, always encrypted).
  • Dovecot stores the mail and serves IMAP (993) and POP3 (995).
  • PostgreSQL holds everything the panels change; Postfix and Dovecot read it directly, so a new mailbox works at once without restarting anything.
  • A small root helper does the few things that need root (mail directories, certificates, updates); every request is checked and written to the audit log.

Installing

  • Appliance — a ready virtual machine (OVA for VMware ESXi and Workstation, qcow2 for Proxmox VE and KVM, VHDX for Hyper-V generation 1) or the installer ISO for a new VM or a physical server (it erases the first disk). Give it at least 2 CPUs, 2 GB of memory and a disk for the mail (the root file system grows by itself when the virtual disk is enlarged). After the first start the screen shows the panel address and the setup token; signing in on the screen as ezadmin (first password emailzit, it must be changed) opens the setup menu: network (use a fixed address for a mail server), server name, time zone, panel address and setup token, password of a staff account, state of the services, restart.
  • Debian 13 package — sudo sh install.sh from the release, or the .deb with apt install: it installs Postfix, Dovecot, Rspamd, Valkey and PostgreSQL from Debian and sets everything up.
  • Ports: 25 (mail from other servers), 465 and 587 (sending from mail programs), 993 (IMAP), 995 (POP3), 8444 (panels and webmail), and 443 and 80 for the automatic setup of mail programs (autoconfig for Thunderbird, Autodiscover for Outlook, the MTA-STS policy; everything else there leads to webmail). EmailZit uses 443 and 80 only when no web server is installed and HostZit is not linked; then HostZit's web server answers for these names (--public-web off turns it off). The server needs a reverse DNS (PTR) name that matches its mail host name, and outgoing port 25 must be open.

Who can do what

  • Administrators manage the server, staff accounts, packages and all customers. Operators manage customers, domains and mailboxes; viewers only look.
  • Customers see and change only their own domains, mailboxes, aliases and forwarders, within the limits of their package.
  • Mail users sign in with their address, their password and always a second factor (an authenticator app). Mail programs (Outlook, Thunderbird, phones) never use this password: every program gets its own app password.

First steps

  1. Set the server's host name under Settings → Mail server (the name mail programs connect to, e.g. mail.example.com).
  2. Create a package with the limits you sell (domains, mailboxes, storage, sending per hour).
  3. Create a customer with that package and give the customer a panel login.
  4. Add the customer's domain, put the DNS records shown on the domain page at the domain's DNS provider, and verify the domain.
  5. Create mailboxes. The mail user signs in at /mail, sets up the second factor and creates app passwords for their programs.
