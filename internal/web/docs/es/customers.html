Clientes y planes

Un plan vale para un buzón

Un plan es el de un solo buzón (Mail 10, Mail 100 …): el tamaño de un buzón nuevo, el tamaño máximo y cuánto puede enviar por hora y por día. El correo se vende por buzón, así que un cliente puede tener varios planes a la vez — por ejemplo tres Mail 10, dos Mail 100 y uno Mail 25. Los sistemas de facturación se refieren a un plan por su nombre corto (por ejemplo mail-10).

Cada cliente tiene además un plan base. Contiene lo que vale para todo el cliente: cuántos dominios y alias, cuánto almacenamiento pueden usar todos los buzones juntos, cuánto puede enviar el cliente por hora y cuántos destinatarios puede tener un mensaje. Un cliente nuevo empieza con tantos buzones del plan base como incluye ese plan.

  • Planes de correo en la página del cliente dice cuántos buzones de cada plan tiene el cliente y cuántos están en uso. Un buzón nuevo se puede crear mientras un plan tenga uno libre, y recibe el tamaño y los límites de envío de ese plan; el personal puede mover un buzón a otro plan más tarde. La API REST escribe lo pedido con PUT /api/v1/customers/{id}/mailbox-packages.
  • Mensajes por hora y por día vienen del plan del propio buzón, y por hora para todo el cliente del plan base. Protegen la reputación de la dirección del servidor: un buzón con la contraseña robada no puede enviar miles de mensajes de spam. Los mensajes por encima del límite esperan en la cola.
  • Destinatarios por mensaje evita que un mensaje vaya a miles de direcciones.
  • Un plan solo se puede quitar cuando no queda ningún buzón suyo, y un plan con buzones no se puede eliminar.

Clientes

Un cliente es dueño de dominios y buzones. El correo de cada cliente se almacena bajo su propio usuario del sistema, de modo que ni siquiera un fallo en el software de correo puede permitir que un cliente lea el correo de otro cliente. Un cliente nunca puede dirigir correo a los buzones de otro cliente, enviar como sus direcciones ni ver sus dominios.

  • Accesos al panel: el cliente inicia sesión en el panel de cliente en la misma dirección que el panel de administración. Cada acceso debe configurar el inicio de sesión en dos pasos en el primer inicio de sesión.
  • ID de facturación: el número del cliente en su sistema de facturación; la API REST encuentra a los clientes por él.
  • Dirección de salida (cuando el servidor tiene direcciones de salida adicionales, consulte Personal, configuración y actualizaciones): el correo del cliente sale desde su propia dirección IP y su propio nombre de host, de modo que su reputación de envío es solo suya. Después, publique el registro SPF que se muestra en cada uno de los dominios del cliente.

Suspender y dar de baja

  • Suspendido: el correo para los dominios del cliente se sigue recibiendo (no se pierde nada), pero nadie del cliente puede iniciar sesión, usar programas de correo ni enviar. Las sesiones terminan al instante.
  • De baja: el correo para los dominios del cliente se rechaza. Los datos se conservan hasta que se eliminan.
  • Activar recupera a un cliente suspendido o dado de baja.
