Primeros pasos

EmailZit es un alojamiento de correo para muchos dominios y clientes en su propio servidor: un panel de administración para el personal del servidor, un panel de cliente donde cada cliente gestiona sus propios dominios y buzones, y páginas para los usuarios de correo (webmail, contraseña propia, contraseñas de aplicación, respuesta automática, filtros).

Cómo está construido

  • Servidor EmailZit: los paneles y la API REST, ejecutándose como un usuario sin privilegios.
  • Postfix recibe y envía el correo (SMTP en el puerto 25, envío para programas de correo en 465 y 587, siempre cifrado).
  • Dovecot almacena el correo y ofrece IMAP (993) y POP3 (995).
  • PostgreSQL guarda todo lo que cambian los paneles; Postfix y Dovecot lo leen directamente, de modo que un buzón nuevo funciona al instante sin reiniciar nada.
  • Un pequeño ayudante root hace las pocas cosas que requieren root (directorios de correo, certificados, actualizaciones); cada solicitud se comprueba y se escribe en el registro de auditoría.

Instalación

  • Appliance: una máquina virtual lista (OVA para VMware ESXi y Workstation, qcow2 para Proxmox VE y KVM, VHDX para Hyper-V generación 1) o la ISO de instalación para una VM nueva o un servidor físico (borra el primer disco). Asígnele al menos 2 CPU, 2 GB de memoria y un disco para el correo (el sistema de archivos raíz crece por sí solo cuando se amplía el disco virtual). Tras el primer arranque, la pantalla muestra la dirección del panel y el token de configuración; al iniciar sesión en la pantalla como ezadmin (primera contraseña emailzit, debe cambiarse) se abre el menú de configuración: red (use una dirección fija para un servidor de correo), nombre del servidor, zona horaria, dirección del panel y token de configuración, contraseña de una cuenta del personal, estado de los servicios, reinicio.
  • Paquete de Debian 13: sudo sh install.sh desde la versión publicada, o el .deb con apt install: instala Postfix, Dovecot, Rspamd, Valkey y PostgreSQL desde Debian y lo configura todo.
  • Puertos: 25 (correo de otros servidores), 465 y 587 (envío desde programas de correo), 993 (IMAP), 995 (POP3), 8444 (paneles y webmail), y 443 y 80 para la configuración automática de los programas de correo (autoconfig para Thunderbird, Autodiscover para Outlook, la política MTA-STS; todo lo demás allí lleva al webmail). EmailZit usa 443 y 80 solo cuando no hay ningún servidor web instalado y HostZit no está vinculado; en ese caso responde el servidor web de HostZit para estos nombres (--public-web off lo desactiva). El servidor necesita un nombre de DNS inverso (PTR) que coincida con su nombre de host de correo, y el puerto 25 saliente debe estar abierto.

Quién puede hacer qué

  • Los administradores gestionan el servidor, las cuentas del personal, los planes y todos los clientes. Los operadores gestionan clientes, dominios y buzones; los observadores solo miran.
  • Los clientes ven y cambian solo sus propios dominios, buzones, alias y reenvíos, dentro de los límites de su plan.
  • Los usuarios de correo inician sesión con su dirección, su contraseña y siempre un segundo factor (una aplicación de autenticación). Los programas de correo (Outlook, Thunderbird, teléfonos) nunca usan esta contraseña: cada programa recibe su propia contraseña de aplicación.

Primeras tareas

  1. Configure el nombre de host del servidor en Configuración → Servidor de correo (el nombre al que se conectan los programas de correo, p. ej. mail.example.com).
  2. Cree un plan: el de un solo buzón — su tamaño y cuánto puede enviar (por ejemplo Mail 10).
  3. Cree un cliente con ese plan base, indique en Planes de correo cuántos buzones de qué plan tiene, y dele un acceso al panel.
  4. Añada el dominio del cliente, ponga los registros DNS que se muestran en la página del dominio en el proveedor DNS del dominio y verifique el dominio.
  5. Cree buzones. El usuario de correo inicia sesión en /mail, configura el segundo factor y crea contraseñas de aplicación para sus programas.
