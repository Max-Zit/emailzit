Premiers pas

EmailZit est un hébergement de messagerie pour de nombreux domaines et clients sur votre propre serveur : un panneau d'administration pour le personnel du serveur, un panneau client où chaque client gère ses propres domaines et boîtes aux lettres, et des pages pour les utilisateurs de messagerie (webmail, mot de passe personnel, mots de passe d'application, réponse automatique, filtres).

Comment il est construit

  • Serveur EmailZit — les panneaux et l'API REST, exécutés sous un utilisateur non privilégié.
  • Postfix reçoit et envoie le courrier (SMTP sur le port 25, soumission pour les logiciels de messagerie sur 465 et 587, toujours chiffrée).
  • Dovecot stocke le courrier et fournit IMAP (993) et POP3 (995).
  • PostgreSQL contient tout ce que les panneaux modifient ; Postfix et Dovecot le lisent directement, de sorte qu'une nouvelle boîte aux lettres fonctionne immédiatement sans rien redémarrer.
  • Un petit assistant root effectue les quelques opérations qui nécessitent root (répertoires de courrier, certificats, mises à jour) ; chaque requête est vérifiée et inscrite dans le journal d’audit.

Installation

  • Appliance — une machine virtuelle prête à l'emploi (OVA pour VMware ESXi et Workstation, qcow2 pour Proxmox VE et KVM, VHDX pour Hyper-V génération 1) ou l'ISO d'installation pour une nouvelle VM ou un serveur physique (il efface le premier disque). Donnez-lui au moins 2 CPU, 2 Go de mémoire et un disque pour le courrier (le système de fichiers racine s'agrandit de lui-même lorsque le disque virtuel est agrandi). Après le premier démarrage, l'écran affiche l'adresse du panneau et le jeton de configuration ; la connexion à l'écran en tant que ezadmin (premier mot de passe emailzit, il doit être changé) ouvre le menu de configuration : réseau (utilisez une adresse fixe pour un serveur de messagerie), nom du serveur, fuseau horaire, adresse du panneau et jeton de configuration, mot de passe d'un compte du personnel, état des services, redémarrage.
  • Paquet Debian 13 — sudo sh install.sh depuis la version publiée, ou le .deb avec apt install : il installe Postfix, Dovecot, Rspamd, Valkey et PostgreSQL depuis Debian et configure tout.
  • Ports : 25 (courrier provenant d'autres serveurs), 465 et 587 (envoi depuis les logiciels de messagerie), 993 (IMAP), 995 (POP3), 8444 (panneaux et webmail), ainsi que 443 et 80 pour la configuration automatique des logiciels de messagerie (autoconfig pour Thunderbird, Autodiscover pour Outlook, la politique MTA-STS ; tout le reste y mène au webmail). EmailZit n'utilise 443 et 80 que lorsqu'aucun serveur web n'est installé et que HostZit n'est pas relié ; sinon, c'est le serveur web de HostZit qui répond pour ces noms (--public-web off le désactive). Le serveur a besoin d'un nom DNS inverse (PTR) qui correspond à son nom d'hôte de messagerie, et le port 25 sortant doit être ouvert.

Qui peut faire quoi

  • Les administrateurs gèrent le serveur, les comptes du personnel, les forfaits et tous les clients. Les opérateurs gèrent les clients, les domaines et les boîtes aux lettres ; les lecteurs ne font que consulter.
  • Les clients voient et modifient uniquement leurs propres domaines, boîtes aux lettres, alias et transferts, dans les limites de leur forfait.
  • Les utilisateurs de messagerie se connectent avec leur adresse, leur mot de passe et toujours un second facteur (une application d'authentification). Les logiciels de messagerie (Outlook, Thunderbird, téléphones) n'utilisent jamais ce mot de passe : chaque logiciel reçoit son propre mot de passe d'application.

Premières étapes

  1. Définissez le nom d'hôte du serveur sous Paramètres → Serveur de messagerie (le nom auquel les logiciels de messagerie se connectent, p. ex. mail.example.com).
  2. Créez un forfait avec les limites que vous vendez (domaines, boîtes aux lettres, stockage, envoi par heure).
  3. Créez un client avec ce forfait et donnez-lui un identifiant pour le panneau.
  4. Ajoutez le domaine du client, placez les enregistrements DNS affichés sur la page du domaine chez le fournisseur DNS du domaine, puis vérifiez le domaine.
  5. Créez des boîtes aux lettres. L'utilisateur de messagerie se connecte sur /mail, configure le second facteur et crée des mots de passe d'application pour ses logiciels.
