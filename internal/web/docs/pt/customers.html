Clientes e planos

Um plano vale para uma caixa de correio

Um plano é o de uma só caixa de correio (Mail 10, Mail 100 …): o tamanho de uma caixa nova, o tamanho máximo e quanto pode enviar por hora e por dia. O correio vende-se por caixa, por isso um cliente pode ter vários planos ao mesmo tempo — por exemplo três Mail 10, dois Mail 100 e um Mail 25. Os sistemas de faturação referem-se a um plano pelo nome curto (por exemplo mail-10).

Cada cliente tem além disso um plano base. Contém o que vale para todo o cliente: quantos domínios e aliases, quanto armazenamento todas as caixas podem usar juntas, quanto o cliente pode enviar por hora e quantos destinatários pode ter uma mensagem. Um cliente novo começa com tantas caixas do plano base quantas esse plano inclui.

  • Planos de correio na página do cliente diz quantas caixas de cada plano o cliente tem e quantas estão em uso. Uma caixa nova pode ser criada enquanto um plano tiver uma livre, e recebe o tamanho e os limites de envio desse plano; o pessoal pode mover uma caixa para outro plano mais tarde. A API REST escreve o pedido com PUT /api/v1/customers/{id}/mailbox-packages.
  • Mensagens por hora e por dia vêm do plano da própria caixa, e por hora para todo o cliente do plano base. Protegem a reputação do endereço do servidor: uma caixa com a senha roubada não consegue enviar milhares de mensagens de spam. As mensagens acima do limite esperam na fila.
  • Destinatários por mensagem evita que uma mensagem vá para milhares de endereços.
  • Um plano só pode ser retirado quando não resta nenhuma das suas caixas, e um plano com caixas não pode ser eliminado.

Clientes

Um cliente é dono de domínios e caixas de correio. O correio de cada cliente é guardado sob o seu próprio utilizador de sistema, por isso nem uma falha no software de correio permite que um cliente leia o correio de outro cliente. Um cliente nunca pode encaminhar correio para as caixas de correio de outro cliente, enviar como os endereços dele nem ver os domínios dele.

  • Acessos ao painel: o cliente inicia sessão no painel do cliente no mesmo endereço do painel de administração. Cada acesso tem de configurar o início de sessão em dois passos no primeiro início de sessão.
  • ID de faturação: o número do cliente no seu sistema de faturação; a API REST encontra os clientes por ele.
  • Endereço de saída (quando o servidor tem endereços de saída adicionais, consulte Pessoal, configurações e atualizações): o correio do cliente sai do seu próprio endereço IP e nome de host, por isso a sua reputação de envio é só sua. Publique depois o registo SPF mostrado em cada um dos domínios do cliente.

Suspender e terminar

  • Suspenso: o correio para os domínios do cliente continua a ser recebido (nada se perde), mas ninguém do cliente consegue iniciar sessão, usar programas de correio ou enviar. As sessões terminam de imediato.
  • Terminado: o correio para os domínios do cliente é recusado. Os dados ficam até serem apagados.
  • Ativar reativa um cliente suspenso ou terminado.
