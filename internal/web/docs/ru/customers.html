Клиенты и тарифы

Тариф относится к одному ящику

Тариф — это тариф одного ящика (Mail 10, Mail 100 …): размер нового ящика, наибольший допустимый размер и сколько он может отправлять в час и в день. Почта продаётся по ящикам, поэтому у одного клиента может быть несколько тарифов одновременно — например три Mail 10, два Mail 100 и один Mail 25. Системы оплаты обращаются к тарифу по короткому имени (например mail-10).

У каждого клиента есть ещё основной тариф. В нём то, что относится ко всему клиенту: сколько доменов и псевдонимов, сколько места могут занимать все ящики вместе, сколько клиент может отправлять в час и сколько получателей может быть у одного письма. Новый клиент начинает с того числа ящиков основного тарифа, которое этот тариф включает.

  • Почтовые тарифы на странице клиента показывают, сколько ящиков каждого тарифа у клиента есть и сколько из них занято. Новый ящик можно создать, пока в тарифе есть свободный, и он получает размер и ограничения отправки этого тарифа; сотрудники позже могут перевести ящик на другой тариф. REST API записывает заказ вызовом PUT /api/v1/customers/{id}/mailbox-packages.
  • Писем в час и в день берётся из тарифа самого ящика, а в час для всего клиента — из основного тарифа. Они защищают репутацию адреса сервера: ящик с украденным паролем не отправит тысячи спам-писем. Письма сверх лимита ждут в очереди.
  • Получателей на письмо не даёт одному письму уйти на тысячи адресов.
  • Тариф можно убрать только тогда, когда не осталось ни одного его ящика, а тариф с ящиками удалить нельзя.

Клиенты

Клиенту принадлежат домены и почтовые ящики. Почта каждого клиента хранится под его собственным системным пользователем, поэтому даже ошибка в почтовом программном обеспечении не позволит одному клиенту прочитать почту другого. Клиент никогда не может направить почту в ящики другого клиента, отправлять от его адресов или видеть его домены.

  • Входы в панель: клиент входит в панель клиента по тому же адресу, что и панель администратора. Для каждого входа при первом входе необходимо настроить двухфакторный вход.
  • ID в биллинге: номер клиента в вашей системе биллинга; REST API находит клиентов по нему.
  • Исходящий адрес (когда у сервера есть дополнительные исходящие адреса, см. «Персонал, настройки и обновления»): почта клиента уходит с его собственного IP-адреса и имени хоста, поэтому его репутация отправителя принадлежит только ему. После этого опубликуйте SPF-запись, показанную на каждом из доменов клиента.

Приостановка и прекращение

  • Приостановлен: почта для доменов клиента по-прежнему принимается (ничего не теряется), но никто из клиента не может войти, пользоваться почтовыми программами или отправлять почту. Сеансы завершаются сразу.
  • Прекращён: почта для доменов клиента отклоняется. Данные сохраняются до их удаления.
  • Активировать возвращает приостановленного или прекращённого клиента.
