入门

EmailZit 是在您自己的服务器上为众多域名和客户提供的邮件托管：面向服务器员工的管理面板、每个客户管理自己的域名和邮箱的客户面板，以及邮件用户页面（网页邮箱、自己的密码、应用密码、自动回复、过滤器）。

系统构成

  • EmailZit 服务器 — 面板和 REST API，以无特权用户身份运行。
  • Postfix 接收和发送邮件（端口 25 上的 SMTP，供邮件程序发信的 465 和 587，始终加密）。
  • Dovecot 存储邮件并提供 IMAP（993）和 POP3（995）服务。
  • PostgreSQL 保存面板所做的一切更改；Postfix 和 Dovecot 直接读取它，因此新邮箱无需重启任何服务即可立即使用。
  • 一个小型 root 助手负责少数需要 root 权限的操作（邮件目录、证书、更新）；每个请求都会经过检查并写入审计日志。

安装

  • 虚拟设备 — 现成的虚拟机（适用于 VMware ESXi 和 Workstation 的 OVA、适用于 Proxmox VE 和 KVM 的 qcow2、适用于第 1 代 Hyper-V 的 VHDX），或用于新虚拟机或物理服务器的安装 ISO（会清除第一块磁盘）。请为其分配至少 2 个 CPU、2 GB 内存和一块用于邮件的磁盘（扩大虚拟磁盘后，根文件系统会自动扩展）。首次启动后，屏幕上会显示面板地址和设置令牌；在屏幕上以 ezadmin 身份登录（初始密码为 emailzit，必须修改）即可打开设置菜单：网络（邮件服务器请使用固定地址）、服务器名称、时区、面板地址和设置令牌、员工账户的密码、服务状态、重启。
  • Debian 13 软件包 — 使用发行版中的 sudo sh install.sh，或通过 apt install 安装 .deb：它会从 Debian 安装 Postfix、Dovecot、Rspamd、Valkey 和 PostgreSQL，并完成全部设置。
  • 端口：25（来自其他服务器的邮件）、465 和 587（邮件程序发信）、993（IMAP）、995（POP3）、8444（面板和网页邮箱），以及用于邮件程序自动配置的 443 和 80（Thunderbird 的 autoconfig、Outlook 的 Autodiscover、MTA-STS 策略；其他所有请求都会转到网页邮箱）。只有在未安装 Web 服务器且未关联 HostZit 时，EmailZit 才使用 443 和 80；否则由 HostZit 的 Web 服务器响应这些名称（--public-web off 可将其关闭）。服务器需要一个与其邮件主机名一致的反向 DNS（PTR）名称，并且出站端口 25 必须开放。

谁能做什么

  • 管理员管理服务器、员工账户、套餐和所有客户。操作员管理客户、域名和邮箱；查看者只能查看。
  • 客户在其套餐的限制范围内，只能查看和更改自己的域名、邮箱、别名和转发。
  • 邮件用户使用自己的地址、密码，并且始终需要第二因素（身份验证器应用）登录。邮件程序（Outlook、Thunderbird、手机）从不使用此密码：每个程序都有自己的应用密码。

最初的步骤

  1. 在设置 → 邮件服务器中设置服务器的主机名（邮件程序连接的名称，例如 mail.example.com）。
  2. 创建一个套餐：单个邮箱的方案 — 它的容量以及可以发送多少（例如 Mail 10）。
  3. 用该基础套餐创建一个客户，在邮件方案中填写它拥有哪个方案的多少个邮箱，并给客户一个面板登录。
  4. 添加客户的域名，将域名页面上显示的 DNS 记录添加到该域名的 DNS 服务商处，然后验证域名。
  5. 创建邮箱。邮件用户在 /mail 登录，设置第二因素，并为自己的程序创建应用密码。
